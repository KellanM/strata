# Handoff: v1.1, made for iPhone Duo (2026-10-31)

For the agent who makes the iOS builds on the Mac. It covers what the `v1.1` branch changes for the iPhone Duo, how to build it, and what only a device or the simulator can check. Read `HANDOFF.md` §4A (building), `docs/handoff-2026-10-29-store-and-builds.md` and `docs/ipad-duo-plan.md` (M1) first; this note doesn't repeat them.

## Where things stand

- **Branch:** `v1.1`, not `master`. The web goes live only when Kellan merges it, so build v1.1 from the branch.
- **Version:** `store/release.json` says **1.1 (8)**. Build 7 (1.0) is the last upload, so 8 keeps the numbers rising across versions. If anything newer than 7 was uploaded, set `build` above it and commit before uploading.
- **Devices:** still **iPhone only**. Keep `TARGETED_DEVICE_FAMILY = 1` (`store/release.json` `"devices": "iphone"`; `tools/ios-configure.mjs` sets it). The Duo is an iPhone, so iPhone-only covers it. iPad is v1.3, and going universal is one-way.

## Building 1.1

1. **Xcode 27.1 and the iOS 27.1 SDK.** This is the only opt-in: there is no Info.plist key. Built with Xcode 26, the app runs on the Duo in compatibility mode, letterboxed at its old size, and earns no badge.
   - First check that Capacitor 8 (`@capacitor/ios` 8.5.x) builds cleanly with Xcode 27.1. If it doesn't, stop and report; don't upgrade Capacitor on your own.
   - `git pull --rebase --autostash` on `v1.1`, `npm ci`, then `npm run build:app` (it ends with `tools/ios-configure.mjs`).
2. **Launch screen.** The iOS 27.1 SDK requires one. Capacitor's template has `LaunchScreen.storyboard` and `UILaunchStoryboardName`, and `ios-configure.mjs` now checks they're there (and puts the key back if the storyboard exists). The icon and splash still come from `npx @capacitor/assets generate`.
3. **Resizing.** `ios-configure.mjs` also removes `UIRequiresFullScreen` if anything adds it: a fold, an unfold and Split View resize the window, and the game is built to follow.
4. Archive and upload with the API key, as before. **Never upload a profiling or autobench build.**

## What changed in the game (for "What to Test")

- **Folding and unfolding keep everything.** The puzzle, the map's place, a lesson, the result, the pause and Finds all carry through a resize. The 3D view re-fits the window, and the map keeps the stone you were looking at in the middle of the screen.
- **On the inner screen the interface is a touch larger** (1.2×): the corner rings, the level's name, the Chisel/Mark switch, the lesson card, and the result's, pause's and map's rings. It applies only in windows at least 600 wide and 600 tall, so a phone and the Duo's outer screen are unchanged.
- **Narrow Split View windows (down to 280 wide)** keep the level's top line on one line: a long chapter name gives way with "…" before the clock and slips do, and the Finds count no longer breaks.

Suggested TestFlight "What to Test":

> Strata now fits the iPhone Duo. Fold and unfold mid-puzzle, on the map, in a lesson and on the result screen; nothing should restart or lose your place. Try it in Split View too.

## Device checks (simulator first, then a real Duo if you can)

The web build was resized in Chromium between 466×678, 669×951, 330×951 and 320×951 in each state below: 36 of 36 resizes passed, with no errors, nothing reset, and the block always framed. Below 280 wide the result's gems start to leave the screen. Only a device can show the native side.

1. **Fold and unfold mid-level, after a few chisels.** The block re-fits with no flash and no restart; chiselled cubes, slips and the clock carry over. Repeat on the map partway down (the same stone stays in the middle), in a lesson, on the result screen, with the pause open, and in Finds.
2. **The system's snap.** The system resizes in one step during a fold. Look for a frame of the old size, stretched or letterboxed, or a black edge.
3. **Split View**, at half the inner screen and as narrow as it goes. Everything should be reachable: the menu ring, the Chisel/Mark switch, the peel diamonds, and Next/Map/Replay.
4. **The fold's crease (real Duo only; the simulator has none).** The crease runs down the middle of the inner screen, which is where the block sits. Check:
   - that you can read the clue numbers on the cubes that lie on the crease, at normal viewing angles;
   - tapping cubes on the crease: a single tap chisels the cube under the finger, and a double tap marks a row;
   - dragging across it: turning the block, and a peel diamond dragged over the crease;
   - pinching to zoom with the fingers on either side of it.
   Report what you see, with a photo if you can. If the crease gets in the way, the fix is a small Capacitor bridge that passes the fold's position (`ReservedRegion`, native only) to the game so the block can sit to one side. **Don't build the bridge unless the test shows a problem.**
5. **Performance on the inner screen.** It has more pixels than a 6.9" iPhone. If the frame rate drops, report it (docs/profiling.md); the pixel ratio can be capped.

## Known, not changed

- On a phone, a level in a long-named chapter (Clockwork Workshop, Lantern Festival) with the clock past 10:00 and several slips breaks the line under the level's name onto two lines. This was already so in 1.0. v1.1 leaves phones exactly as they were, and fixes it only in narrow Split View windows.
